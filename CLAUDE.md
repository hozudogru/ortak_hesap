## What this app is

**Ortak Hesap** is a shared expense tracker mobile app (Flutter + Firebase). Users create or join groups, log expenses with flexible split modes, track who owes whom, and settle debts via payment requests. UI strings are localized (Turkish default, English, German); code comments, commit messages and Cloud Function log/notification text are Turkish.

## Commands

Run Flutter commands from the repo root; Cloud Functions commands from `functions/`.

```
flutter pub get                        # install/sync Dart dependencies
flutter analyze                        # static analysis (flutter_lints; platform dirs excluded in analysis_options.yaml)
flutter run                            # run on a connected device/emulator
flutter build apk|appbundle|ios        # local builds (CI release builds go through Codemagic — see the `release` skill)
dart run flutter_launcher_icons        # regenerate Android launcher icons from assets/icon*.png (iOS is deliberately off — it rewrites pbxproj)

cd functions
npm install
npm run serve                          # firebase emulators:start --only functions
npm run deploy                         # firebase deploy --only functions
npm run logs                           # firebase functions:log
firebase deploy --only firestore:rules # push firestore.rules (run from repo root)
```

**There are no meaningful tests.** `test/widget_test.dart` is the Flutter counter-template test and fails against the real app, so `flutter test` is not a useful signal. Verify debt/split changes by running the app.

Release builds (version bumping in `pubspec.yaml`, Codemagic Android/iOS workflows, signing) are handled by the `release` skill — use it rather than reconstructing the process by hand.

## Architecture

### Nearly single-file Flutter app
- **`lib/main.dart`** (~5800 lines) holds every screen, dialog, Firestore access, the debt algorithm, PDF export and notification setup. No state management package; `StreamBuilder` over Firestore + `setState`.
- **`lib/l10n/`** — `AppLocalizations` with `t(key, {params})` lookup over three flat `Map<String,String>` files (`strings_tr/en/de.dart`). Missing keys fall back to Turkish, then to the key itself. `{name}`-style placeholders are substituted from `params`. Add every new key to all three maps.
- **`lib/services/social_auth_service.dart`** — Google (`google_sign_in` v7 API: `initialize` once, then `authenticate`) and Apple (`sign_in_with_apple` + SHA-256 nonce) sign-in, re-authentication for account deletion, and Apple token revocation. Apple is iOS-only (`isAppleAvailable`). OAuth client ids are hard-coded there because `GoogleService-Info.plist` is not part of the Xcode target; the reversed iOS client id is also registered as a URL scheme in `ios/Runner/Info.plist`. `completeSocialSignIn` in main.dart writes `users/{uid}` without overwriting an existing name (Apple only supplies the name on first sign-in). The `SocialSignInButtons` widget is shared by `LoginPage` and `RegisterPage`.
- **`lib/services/version_check_service.dart`** — on HomePage init, reads `config/appVersion` (`minVersion`, `latestVersion`, `iosUrl`, `androidUrl`) and shows an optional or mandatory (non-dismissible) update dialog.
- **`lib/firebase_options.dart`** — generated by FlutterFire CLI for project `ortak-hesap-app-cd595`; don't hand-edit.

### Firestore data model

```
groups/{groupName}                    ← group name IS the document ID (must be unique; renaming unsupported)
  .currency, .ownerId, .memberIds[], .groupCode (6-digit code used for joining)
  /members/{uid}                      ← email, name, nickname, role, isAnonymous
  /expenses/{auto-id}                 ← title, amount, currency, paidBy (email), participants[], splitType, category, shares{}, createdByUid
  /payments/{auto-id}                 ← fromEmail, toEmail, amount (settled debts; reduce balances)
  /paymentRequests/{auto-id}          ← fromEmail, toEmail, amount, status: pending|approved|rejected
  /_merge_backups/{auto-id}           ← snapshot written before an anonymous→real member merge (mergedFrom, mergedInto, affected expenses)

users/{uid}                           ← email, name, nickname, fcmToken
notificationRequests/{auto-id}        ← toEmail | toEmails[], fromEmail, type, groupName, title?, body?, isRead, status, createdAt
config/appVersion                     ← read-only from the app (see version check above)
```

**Members are keyed by email everywhere in expenses/payments/balances**, not by uid. Emails are normalized with `trim().toLowerCase()` before writes and comparisons — keep doing that.

### Expense split types and money math
- `equal` — amount divided across participants; `custom` — exact per-participant amounts; `weighted` — weights converted to amounts.
- `splitExpenseShares` (top of main.dart) produces **cent-exact** shares: every value goes through `roundCents`, and the rounding remainder is assigned to the payer (or the first participant). This is what keeps balances from showing phantom 0.01 amounts — reuse it rather than dividing inline.
- `kBalanceEpsilon` (0.005) is the threshold for "balanced"; use it instead of `== 0` comparisons.

### Debt calculation
Inside `_GroupDetailPageState`: `calculateBalanceFromExpenses` → `applyPaymentsToBalance` → `calculateDebtsFromBalance`. Balance >0 means owed-to, <0 means owes. Greedy matching: sort debtors and creditors descending, pair largest with largest, to minimise transaction count. The PDF export duplicates this logic inline (search `paymentPlan`) — change both if you change the algorithm.

### Settling a debt (payment requests)
From the Debts tab a debtor sends a `paymentRequests` doc (status `pending`) plus a `notificationRequests` doc of type `payment_request`. The creditor approves/rejects from `NotificationsPage`; approval is a single batch that writes a `payments` doc, flips the request to `approved`, and emits a `payment_approved` notification. A creditor can also record a received payment directly (`payment_received_info`).

### Anonymous members and merging
Members can be added without an account (`isAnonymous: true`); their email is a generated `anonymous_<name>_<timestamp>` string. `resolveDisplayName` maps an email to a display name: the stored member name/nickname if present, else a title-cased name parsed out of the `anonymous_` id, else the part of the email before `@`. `mergeMember` rewrites an anonymous email to a real member's email across expenses, checking that the balance sum is unchanged before and after and aborting otherwise; it writes a `_merge_backups` doc first.

### Push notifications
- App writes to `notificationRequests`; `functions/index.js` (`sendNotificationRequest`, firebase-functions v2, Node 22) looks up each recipient's `fcmToken` by email, sends via FCM multicast, marks the doc `sent`/`failed`, and deletes tokens FCM reports as unregistered.
- If the request has no `title`/`body`, the function builds Turkish fallback text from `type` (`expense_added`, `debt_reminder`, `payment_request`, `payment_approved`, `payment_rejected`, `payment_received_info`). Adding a new type means updating `buildFallbackMessage` too.
- Android notification sound relies on channel id `ortakhesap_sound_v3` being created identically in `main.dart` (`_highImportanceChannel`) and referenced in the function; iOS uses `coin.wav`. Keep the two in sync.
- `cleanupOldNotificationRequests` runs daily at 03:00 Europe/Istanbul and deletes requests older than 30 days.

### Firestore security rules
`firestore.rules` — everything requires `request.auth != null`, with these extras: group `create` requires `ownerId == request.auth.uid`; group `delete` requires caller to be the owner; expense `update`/`delete` requires caller to be `createdByUid` or the group owner; `config/*` is read-only. Always set `createdByUid` when creating expenses or the creator loses edit rights.
