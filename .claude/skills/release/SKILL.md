# Release process

Two workflows in `codemagic.yaml`, both pinned to Flutter 3.47.9. There is no `triggering` section, so a push does **not** start a build: after pushing, start each workflow by hand in the Codemagic UI (app → Start new build → pick the workflow and the `main` branch).

- **`android-workflow`**: builds an AAB, signs with the `Ortak_Hesap_Takip` keystore (env vars `CM_KEYSTORE`, `CM_KEYSTORE_PATH`), publishes to the Google Play **production** track via `GPLAY_SERVICE_ACCOUNT_JSON`. Play Console still requires a manual review/rollout of the release it creates.
- **`ios-workflow`**: `ios_signing` (distribution_type app_store, bundle id `com.hasimozudogru.ortakhesap`, team L8VSGNGQPG) builds the IPA and submits to TestFlight via the `Codemagic3` App Store Connect integration.

  **How iOS signing really works here (learned the hard way, Nov 2026):** `ios_signing` only *selects* a certificate and profile from Codemagic's own store (personal account → **Settings → codemagic.yaml settings → Code signing identities**). It does **not** create or refresh profiles from Apple. Current store entries: certificate `ortakhesap_dist` (generated by Codemagic with the Codemagic3 key, so Codemagic holds the private key) and profile `ortakhesap_appstore` (Apple name `ortakhesap-appstore-2026-v2`).
  - Error `Provisioning profile "..." doesn't include the X capability` ⇒ the stored profile predates an App ID capability change. Fix: in Apple Developer → Profiles, regenerate (or create) the App Store profile for the App ID using the Codemagic-generated distribution certificate, then in Codemagic → Code signing identities → iOS provisioning profiles → **Fetch profiles** (Codemagic3) and replace the stored one. Deleting things in Apple's portal alone changes nothing, because the stale copy lives in Codemagic.
  - Error `No matching profiles found for bundle identifier ...` ⇒ the Codemagic store has no profile; fetch one as above.
  - Error `No matching certificate found for every requested profile` ⇒ the profile is bound to a certificate whose private key Codemagic doesn't have; edit the profile in Apple's portal to use the Codemagic-generated certificate, then fetch again.
  - The build log artifact (`xcodebuild_logs/Runner.log`, downloadable as the build's artifacts zip) contains the real `error:` lines; the step output only says "Failed to archive".

Version bumping: update `version` in `pubspec.yaml` (format: `1.0.0+<build-number>`). The build number maps to Android `versionCode` and iOS `CFBundleVersion` — App Store Connect rejects a build whose `CFBundleVersion` doesn't strictly exceed every previously uploaded value, so bump it even for a resubmit of the same source. Commit messages for releases follow `feat|fix: release X.Y.Z — summary`.

After the stores accept the build, update `config/appVersion` in Firestore (`latestVersion`, optionally `minVersion`) so the in-app update prompt matches.

Manual local build commands:
```bash
flutter build appbundle --release            # Android AAB for Play Store
flutter build ios --release --no-codesign    # iOS (Codemagic handles signing)
```

Firebase Functions deploy (in `functions/`):
```bash
cd functions && npm install
firebase deploy --only functions
```
